## ReviewOps v1.0.0

The first stable release. ReviewOps reviews pull requests with an AI model and posts the findings as one review with inline comments.

Use it with the moving major tag, or pin it to the commit of this release:

```yaml
uses: lucalipsxstroons1/ReviewOps@v1
```

See the [README](https://github.com/lucalipsxstroons1/ReviewOps#readme) for the quick start, every input and output, and the security notes.

### What it does

- Runs on new, updated and reopened pull requests, reads the diff through the GitHub API and sends it to the OpenAI API.
- Focus areas: code quality, React, EF Core and security. Every finding has a severity and a category.
- Comments only at added lines. The action calculates the line numbers itself and checks every finding of the model against the diff.
- A new push reviews only what is new and never repeats a comment.
- Files that may hold secrets are never sent, and strings that look like secrets are masked before anything is sent.
- Leaves out the review of drafts, of pull requests with the label `no-ai-review` and of pull requests that a bot opened (inputs `review-drafts`, `skip-label` and `review-bots`). A draft that is marked ready, or a pull request whose skip label is taken off, gets its review then. A run that leaves out the review asks no model and still applies `fail-on`.
- Posts one review of the type `COMMENT`. It never approves a pull request and never requests changes. `fail-on` can let the step fail on open findings.
- Writes a job summary and sets the outputs `findings-count`, `critical-count` and `review-url`.
- Can send a report with key figures of every review (token usage, duration, severity, category and file path of each finding, never code and never a text of the model) to a [ReviewOps Insights](https://github.com/lucalipsxstroons1/ReviewOps-Insights) instance. It is off by default and switched on with the inputs `insights-url` and `insights-secret`. The report is signed, a report that does not arrive never changes the result of the step, and the README and `SECURITY.md` say what is sent.
- Feedback in twelve languages (`language`).

### Default model

The default model is `gpt-6-luna`. It was chosen by comparing three models on twelve pull requests, three runs each, and by checking the false alarms against the code (issues [#41](https://github.com/lucalipsxstroons1/ReviewOps/issues/41) and [#83](https://github.com/lucalipsxstroons1/ReviewOps/issues/83)). It costs about a fourteenth of `gpt-6.1-sol` per review. `gpt-4o-mini` missed security defects that both newer models found and is no longer the default. Any model that supports Structured Outputs works through the input `openai-model`.

### Known limitations

The model finds only part of the real defects, and it sometimes raises a false alarm. Treat the review as a help, not as a check. The README lists the known limitations under [Known limitations](https://github.com/lucalipsxstroons1/ReviewOps#known-limitations).

### Versions

Patch releases fix bugs. Minor releases add inputs and behaviour that can be switched off. A new default model, or an input that is removed or renamed, is a major release. The tag `v1` moves with every release of version 1. See [docs/release.md](https://github.com/lucalipsxstroons1/ReviewOps/blob/main/docs/release.md).
